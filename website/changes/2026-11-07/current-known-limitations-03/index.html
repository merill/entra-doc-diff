Microsoft Entra Global Secure Access
General

Current Known Limitations

7 November 2026Doc updateAction required+6 / −5 lines

In brief

The known-limitations page now says end-to-end QUIC forwarding is unsupported, while cloud firewall supports QUIC acquisition and blocking in preview. Administrators should keep browser QUIC enabled, use Custom Acquire for UDP 443 traffic, and apply a cloud firewall policy through the relevant security profile.

What Entra admins need to know

Update configurations that disable browser QUIC to use the documented Custom Acquire and cloud firewall approach.

The Global Secure Access client doesn't support concurrent sessions on the same machine. This limitation applies to Remote Desktop Protocol (RDP) servers and Virtual Desktop Infrastructure (VDI) solutions like Azure Virtual Desktop (AVD) that are configured for multi-session.

QUIC not supported for Internet Access

SinceEnd-to-end QUIC forwarding isn't yet supported in Internet Access. Cloud firewall for Internet Access, traffic to ports 80 UDPclients supports QUIC acquisition and 443 UDP can't be tunneled.blocking in preview.

!Tip

QUIC is currently supported in Private Access and Microsoft 365 workloads.

Keep QUIC enabled in browsers. Use Custom Acquire to acquire UDP traffic on destination port 443 for the intended destinations, and use cloud firewall to block that traffic. Apply the firewall policy through the security profile for the intended users. Applications that support fallback can then use HTTPS over TCP. Default Acquire on TCP port 443 doesn't acquire UDP port 443, and an Allow rule doesn't enable supported end-to-end QUIC forwarding. For configuration and verification steps, see Control QUIC traffic on UDP port 443.

WSL 2 connectivity

When the Global Secure Access client for Windows is enabled on the host machine, outgoing connections from the Windows Subsystem for Linux (WSL) 2 environment might be blocked. To fix this issue, create a .wslconfig file that sets dnsTunneling to false. This way, all traffic from the WSL bypasses Global Secure Access and goes directly to the network. For more information, see Advanced settings configuration in WSL.

  • If the network is in shared mode, you can install the Global Secure Access client on a virtual machine running macOS, as long as the client isn't also installed on the host machine.
