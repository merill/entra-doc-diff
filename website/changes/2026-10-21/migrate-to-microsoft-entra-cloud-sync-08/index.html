Migrating from Microsoft Entra Connect to Microsoft Entra Cloud Sync

Microsoft Entra Cloud Sync synchronizes users, groups, and contacts from Active Directory to Microsoft Entra ID by using the Microsoft Entra provisioning agent. When device sync is enabled, Cloud Sync can also synchronize computer objects for Microsoft Entra hybrid join. Use this guide to choose a migration path from Microsoft Entra Connect Sync and plan a phased migration fromwhen a documented manual procedure applies.

Choose a migration path

Start with the migration decision guide to check Cloud Sync platform capabilities. Then review the separate guided migration-tool prerequisites and limits.

Migration pathWhen to use it
Guided migration toolThe migration option appears on the active Connect Sync server and the readiness review confirms that the environment is eligible.
Manual phased migrationCloud Sync supports the required scenario, the guided tool doesn't support it, and Microsoft Entraprovides a documented manual migration procedure.
Continue using Connect to Cloud Sync.

Sync		A required capability or documented migration procedure isn't currently available. Review the decision guide.

Steps for migrating from Microsoft Entra Connect to Cloud Sync

!Important

During the pilot or coexistence phase, don't remove OUs, domains, groups, users, contacts, or other referenced objects from Microsoft Entra Connect Sync scope. Keep the existing scope configured until objects are fully migrated and you're ready for final cutover. Removing objects from scope before final cutover is unsafe: it can drop references in the Microsoft Entra connector space and export reference deletes (such as group membership removals) to Microsoft Entra ID.

The supported coexistence model is to keep objects in Microsoft Entra Connect Sync scope and use the cloudNoFlow and JoinNoFlow rules to prevent Microsoft Entra Connect Sync from exporting object adds, object deletes, and non-reference attribute updates. Reference attribute updates, such as member and manager, can still flow for reference resolution.

!Important

During a phased migration, don't remove organizational units (OUs), domains, groups, users, contacts, or other referenced objects from Connect Sync scope before migration and reference validation are complete. Removing scope too early can result in unintended reference removals, such as group membership removals in Microsoft Entra ID. Review Plan scope removal from Microsoft Entra Connect Sync.

The following process describes manual phased migration. If your environment is eligible, use the guided migration tool instead.

  • In scope means the object remains represented in the synchronization configuration.
  • Export authority means the synchronization engine responsible for exporting normal changes.
  • During the documented manual pilot, objects remain in Connect Sync scope while cloudNoFlow and JoinNoFlow prevent normal Connect Sync exports.
  • Remove objects from Connect Sync scope only after Cloud Sync migration and reference validation are complete.
