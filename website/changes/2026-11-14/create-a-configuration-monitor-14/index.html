Create a configuration monitor

14 November 2026Feature update+36 / −18 lines

In brief

The documentation now covers creating monitors for home and connected governed tenants, including target-tenant selection, governance relationships, delegated permissions, baseline templates, and governed-tenant naming rules. It also clarifies that Tenant Governance Premium is not required solely for cross-tenant monitoring.

What Entra admins need to know

Administrators can monitor connected tenants, but must use a Global Administrator account and configure the required governance relationship, delegated permissions, and resource access for cross-tenant monitors.

Configuration monitors evaluate a tenant against a configuration baseline and report configuration drift. Use a monitor when you want to track whether a tenant stays aligned with a known-good configuration.

Configuration management supports operations in the home tenant and in other tenants that are connected through governance relationships.

Prerequisites

  • Sign in to the Microsoft Entra admin center as a Global Administrator.
  • The tenant has licenses for Tenant Governance Basic or Tenant Governance Premium. Basic includes monitoring in the home tenant and governed tenants; Premium isn't required solely for cross-tenant monitoring. For current licensing requirements,requirements and resource capacity, see Microsoft Entra Tenant Governance licensing.
  • Tenant Governance Basic includes a quota for the number of resources that you can monitor. If the resources in the monitor cause the tenant to exceed its quota, monitor creation fails. An organization gets additional quota for monitored resources for each Tenant Governance Premium license it has.
  • The signed-in user is in a Microsoft Entra privileged role and has permission to create configuration monitors. The user must alsoYou have read permissions for the resource types included in the monitor's configuration baseline.
  • The Tenant Configuration Management service has permissions for the workloads and resource types included in the monitor baseline. To assign or remove permissions for the service, see Configure configuration management service permissions.
  • For monitoring another tenant, an active governance relationship connects your tenant to the governed tenant. Configure the required delegated permissions and ensure that your delegated roles allow you to read the selected resources in that tenant.

Start monitor creation

To start creating a configuration monitor, follow these steps:

  1. Sign in to the Microsoft Entra admin center as a user with the required role and permissions.Global Administrator.
  2. Browse to Tenant Governance >. Under Tenant management, select Monitors. for the home tenant. Under Other tenants, select Monitors (Preview) for a governed tenant.
  3. Select New monitor.

:::image type="content" source="../media/tenant-governance-configuration-management/monitors-overview.png" alt-text="Screenshot of the monitor list with the New monitor command and Tenant Governance navigation." lightbox="../media/tenant-governance-configuration-management/monitors-overview.png":::

Complete the monitor wizard

Complete the wizard steps to configure and create the monitor:

  1. For a governed-tenant monitor, select the target tenant on Tenants. This step isn't shown for home-tenant monitors, which use your current tenant.

  2. On Settings, enter a unique monitor name of at least eight characters and an optional description. Governed-tenant monitor names must contain 8 to 256 characters and use only letters, numbers, and spaces.

  3. On Configuration baseline, upload a baseline JSON file orfile, select Import from snapshot., or select a configuration baseline template. If you select Import from snapshot, search by snapshot name, select a snapshot, and then select Import. You can use the in-page editor to manually compose or edit the configuration baseline.

  4. On Permissions, review the service's application permissions and role assignments for the selected target tenant, including whether the service has permission to:

    • Read the required Microsoft Graph resources, to monitor Microsoft Entra or Intune resources.
    • Authenticate to Exchange, to monitor Exchange, Defender, or Purview resources.
    • Use the Teams Reader role, to monitor Teams resources.
!Note

This step is read-only. It doesn't evaluate whether the user is authorized to create a monitor with the selected resources. It also doesn't show or validate whether the permissions assigned to the configuration management service locally within Exchange Online, Defender, or Purview are sufficient to create a monitor with resources in those services.

  1. If readiness shows missing permissions, configure them on Configuration management permissions, and then review readiness again. For another tenant, also verify that the governance relationship and delegated access are active.
  2. On Review, verify the target tenant and baseline, review the summary, and create the monitor.

After you create the monitor, it runs automatically on its schedule. Results are available after the first run completes. The home-tenant wizard in earlier versions of the experience shows Permissions before Configuration baseline, rather than starting with Settings.

To learn how to review monitor results and configuration drift, see View monitor results and manage monitors.

Troubleshoot other-tenant monitoring (Preview)

The governed-tenant monitor list shows the target tenant for each monitor.

:::image type="content" source="../media/tenant-governance-configuration-management/governed-tenant-monitors.png" alt-text="Screenshot of governed-tenant monitors showing the target tenant and status of each monitor." lightbox="../media/tenant-governance-configuration-management/governed-tenant-monitors.png":::

If the target tenant isn't available, verify the governance relationship and your access to that tenant. If creation or a later run fails, review the error and permission readiness for the target workload. Relationship changes, removed consent, or missing workload-specific roles can prevent later runs even if monitor creation succeeded.
