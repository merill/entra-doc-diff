What is Privileged Identity Management?

17 November 2026New feature+26 / −8 lines

In brief

The guidance now covers eligible and active assignments for application-defined roles, including management, activation, requests, and approvals. It also documents the Microsoft Entra ID Governance licensing requirement and warns that activation or approval may not immediately grant application access.

What Entra admins need to know

Administrators should verify Governance license coverage for eligible or time-bound assignment users and request approvers, and review the documented app-role permissions and activation workflow.

What is Microsoft Entra Privileged Identity Management?

PIM also supports eligible and active assignments for application-defined roles through PIM for app roles (preview). Users can activate eligible app roles when they need them and deactivate them when they finish.

Reasons to use

Organizations want to minimize the number of people who have access to secure information or resources, because that reduces the chance of

[!INCLUDE entra-id-license-pim.md]

PIM for app roles (preview) requires Microsoft Entra ID Governance licenses. Microsoft Entra ID P2 alone isn't sufficient.

License coverage is required for users with eligible or time-bound app role assignments and for request approvers.

What does it do?

  • Download audit history for internal or external audit
  • Prevent removal of the last active Global Administrator and Privileged Role Administrator role assignments

The available capabilities depend on the PIM provider. For the app roles preview's workflows, see PIM for app roles (preview).

What can I do with it?

Once you set up Privileged Identity Management, you'll see Tasks, Manage, and Activity options in the left navigation menu. As an administrator, you can choose between options such as managing Microsoft Entra roles, managing Azure resource roles, or PIM for Groups. When you choose what you want to manage, you see the appropriate set of options for that option.

For app role assignments, select App Roles (Preview), and then select an application. From the application, you can manage assignments and role settings, activate your eligible roles, and review requests.

:::image type="content" source="./media/pim-configure/pim-quickstart.png" alt-text="Screenshot of Privileged Identity Management in the Azure portal.":::

Who can do what?

For Azure resource roles in Privileged Identity Management, only a subscription administrator, a resource Owner, or a resource User Access Administrator can manage assignments for other administrators. Users who are Privileged Role Administrators, Security Administrators, or Security Readers don't by default have access to view assignments to Azure resource roles in Privileged Identity Management.

For app role assignments, owners of the target service principal and users with a supported administrative role can create, update, and remove assignments. For the supported roles, see Permissions for app role assignments (preview).

Terminology

To better understand Privileged Identity Management and its documentation, you should review the following terms.

Assign

The assignment process starts by assigning roles to members. To grant access to a resource, the administrator assigns roles to users, groups, service principals, or managed identities. The supported assignment subjects depend on the PIM provider. The assignment includes the following data:

  • The members or owners to assign the role.
  • The scope of the assignment. The scope limits the assigned role to a particular set of resources. :::image type="content" source="./media/pim-configure/role-assignment.png" alt-text="Screenshot of Privileged Identity Management role assignment.":::

For more information, check out the following articles: Assign Microsoft Entra roles, Assign Azure resource roles, Assign eligibility for a PIM for Groups, and Assign eligibility for a PIM for GroupsAssign app roles (preview).

Activate

If the role requires approval to activate, a notification appears in the upper right corner of the user's browser informing them the request is pending approval. If an approval isn't required, the member can start using the role.

For app roles (preview), don't assume that completing PIM activation immediately changes application access. See the app role activation considerations.

For more information, check out the following articles: Activate Microsoft Entra rolesActivate Microsoft Entra roles, Activate my Azure resource rolesActivate my Azure resource roles, Activate my PIM for Groups roles, and Activate my PIM for Groups rolesActivate app roles (preview).

Approve or deny

Delegated approvers receive email notifications when a role request is pending their approval. Approvers can view, approve, or deny these pending requests in PIM. After the request is approved, the member can start using the role. For example, if a user or a group was assigned with Contribution role to a resource group, they can manage that particular resource group.

For app roles (preview), approval alone doesn't confirm that the application has started granting access. See the app role activation considerations.

For more information, check out the following articles: Approve or deny requests for Microsoft Entra roles, Approve or deny requests for Azure resource roles, Approve activation requests for PIM for Groups, and Approve activation requests for PIM for GroupsApprove or deny app role requests (preview).

Extend and renew assignments

  • Extend – When a role assignment nears expiration, the user can use Privileged Identity Management to request an extension for the role assignment
  • Renew – When a role assignment expires, the user can use Privileged Identity Management to request a renewal for the role assignment

BothFor Microsoft Entra role assignments, both user-initiated actions require an approval from a Global Administrator or Privileged Role Administrator. Admins don't need to be in the business of managing assignment expirations. You can just wait for the extension or renewal requests to arrive for simple approval or denial.

For more information, check out the following articles: Extend or renew Microsoft Entra role assignments, Extend or renew Azure resource role assignments, Extend or renew PIM for Groups assignments, and Extend or renew PIM for Groups assignmentsExtend or renew app role assignments (preview).
