Create a lifecycle workflow - Microsoft Entra ID

17 November 2026Feature update+35 / −11 lines

In brief

The article now documents identity-verification onboarding templates, required verification profiles, template-specific trigger settings, and the distinction between enabling a workflow and enabling scheduled runs.

What Entra admins need to know

Administrators creating these workflows must select a profile with purpose `all` or `onboarding`; they can test workflows on demand before enabling scheduled processing.

!Important

In the Microsoft Entra admin center, a newly created workflow is enabled (isEnabled is true), but scheduling is disabled (isSchedulingEnabled is false) unless you select the scheduling checkbox. This lets you run the workflow on-demand. for a small audience before enabling scheduled processing. Disabling the workflow itself (isEnabled is false) prevents both scheduled and on-demand runs.

Create a lifecycle workflow by using Microsoft Graph

To create a lifecycle workflow by using the Microsoft Graph API, see Create workflow.

Next steps

  • Manage a workflow's properties

    For API creation, explicitly set isEnabled and isSchedulingEnabled for the intended run mode. The values you set control workflow execution and scheduling; don't assume the admin center's checkbox defaults apply to an API request.

    The three Preview tasks used by the two identity-verification templates are available only in Microsoft Graph /beta, not /v1.0. To create a workflow that includes these tasks, see Create workflow (beta). For task definitions and arguments, see Lifecycle workflow tasks.

    !Note

    Microsoft Graph beta APIs are subject to change. Use of these APIs in production applications isn't supported.
