### Select verification profile for identity verification (Preview)

This task selects an identity verification profile and sends the user an identity verification email during pre-hire onboarding. It's included in the [Pre-hire identity verification initiation (Preview)](lifecycle-workflow-templates.md#pre-hire-identity-verification-initiation-preview) template.

You can customize the task name and description in the Microsoft Entra admin center. The task shows the **Verified ID Profile** selected for the workflow. To select or change that profile, use the workflow's **Select identity verification profile** page.

:::image type="content" source="media/lifecycle-workflow-task/identity-verification-profile-task.png" alt-text="Screenshot of the pre-hire identity verification task settings, with User as the recipient and otherMails as the recipient email address property." lightbox="media/lifecycle-workflow-task/identity-verification-profile-task.png":::

The prerequisites to run the **Select verification profile for identity verification (Preview)** task are:

- An ID verification profile with purpose set to `all` or `onboarding`, selected for the workflow. For profile configuration, see [Create an ID verification profile](../verified-id/how-to-create-id-verification-profile.md).
- A populated `otherMails` attribute for the user, containing an email address the user can access.

The default email settings are **User (default)** for **To recipient** and **otherMails** for **To recipient email address property**. You can also select **CC recipients**.
!Important

Access to the pre-hire identity verification link sent to the user's otherMails address is secured with an email one-time passcode (OTP). In the current release, otherMails is the only supported and recommended recipient email address property for this task. Other custom extension attributes can appear in To recipient email address property, but email OTP protection isn't supported for those attributes. Use otherMails rather than a custom extension attribute.

[!NOTE] You can customize the email subject, message body, and language under Email Customization. For details, see Common email task parameters and Customize emails sent from workflow tasks.

This task is available only in Microsoft Graph /beta, not /v1.0. See Lifecycle Workflows overview (beta).

Send manager verification status email (Preview)

This task sends the user's manager an email about the employee's verification status. It's included in both the Pre-hire identity verification initiation (Preview) and New Hire employee onboarding with identity verification (Preview) templates.

You can customize the task name and description in the Microsoft Entra admin center. The task shows the Verified ID Profile selected for the workflow. To select or change that profile, use the workflow's Select identity verification profile page.

:::image type="content" source="media/lifecycle-workflow-task/manager-verification-status-email-task.png" alt-text="Screenshot of the manager verification status email task settings, with Manager as the recipient and mail as the recipient email address property." lightbox="media/lifecycle-workflow-task/manager-verification-status-email-task.png":::

The prerequisites to run the Send manager verification status email (Preview) task are:

  • An ID verification profile with purpose set to all or onboarding, selected for the workflow.
  • For the default manager recipient, a populated manager attribute for the user and a populated mail attribute for that manager.

The default email settings are Manager (default) for To recipient and mail for To recipient email address property. You can also select CC recipients.

!Note

You can customize the email subject, message body, and language under Email Customization. For details, see Common email task parameters and Customize emails sent from workflow tasks.

This task is available only in Microsoft Graph /beta, not /v1.0. See Lifecycle Workflows overview (beta).

Select verification for Verified ID presentation (Preview)

This task sends the user a link to present a Verified ID based on government ID verification completed through a security partner. It's included in the New Hire employee onboarding with identity verification (Preview) template.

Inline passkey registration through this task isn't supported on iOS when the applicable passkey profile has Enforce attestation enabled, or for Android work-profile passkey registration. On Android, the inline flow uses the Verified ID in Microsoft Authenticator's personal profile and registers the passkey in that profile, not the work profile. For eligible accounts, use the existing TAP task instead, with recommended Conditional Access protection for registration. See Choose a Day 1 registration path.

Inline passkey registration isn't supported for internal or external guest accounts. The current preview doesn't change this passkey guest restriction.

You can customize the task name and description in the Microsoft Entra admin center. The task shows the Verified ID Profile selected for the workflow. To select or change that profile, use the workflow's Select identity verification profile page.

Generate Temporary Access Pass and send via email to user's manager

Microsoft Entra allows you to use a [Temporary Access Pass (TAP)](..//identity/authentication/howto-authentication-temporary-access-pass.md)Temporary Access Pass (TAP) to set up password-less credentials for users. You can also use [Microsoft Entra self-service password reset](../identity/authentication/concept-sspr-howitworks.md)Microsoft Entra self-service password reset to set a regular password. With this task, Lifecycle workflows allowWorkflows can automatically generate a TAP and email it to the selected recipient. The task catalog name refers to manager delivery, but you can also select the user as the recipient.

To send the TAP to automatically generatethe user, under Basics, set To recipient to User and To recipient email address property to otherMails. The user's otherMails attribute must contain an email address the user can access. Update Task description to reflect delivery to the user, for example, "Generate a Temporary Access Pass (TAP), and haveemail it sent to the new user's manager.user." You're also able to can customize the email that is sentunder Email Customization.

For the employee Day 1 alternative to inline passkey registration, see Configure TAP with identity-verification-protected registration. The recommended configuration uses a Conditional Access policy for Register security information with Require identity verification. This policy isn't required to use the userTAP alternative; sending a TAP alone doesn's manager. t establish identity verification.

!Note

The user's employee hire date is used as the start time for the Temporary Access Pass. Make sure that the TAP lifetime task setting and the time portion of your user's hire date are set appropriately so that the TAP is still valid when the user starts their first day. If the hire date at the time of workflow execution is already in the past, the current time is used as the start time.

The Microsoft Entra prerequisites to run the Generate Temporary Access Pass and send via email to user's manager task are:

  • AFor delivery to the manager, a populated manager relationship for the user and a populated mail attribute for the user.manager.
  • AFor delivery to User/otherMails with the default email body, a populatedmanager relationship for the user. The manager's mail attribute isn't required.
  • For delivery to User/otherMails with a custom email body, the default-body requirement for the user.a populated manager relationship doesn't apply.
  • The TAP tenant policy must be enabled and the selected values for activation duration and one time use must be within the allowed range of the policy. For more information, see Enable the Temporary Access Pass policy
!Important

A user having this task run for them in a workflow must also not have any other authentication methods, sign-ins, or Microsoft Entra role assignments for this task to work for them.

TAP account-type restrictions apply independently of email delivery. Internal guest accounts can be issued a TAP, but external guest accounts can't be issued one in the resource tenant. See TAP guest access for the account-type and home-tenant sign-in requirements.

For eligible internal guests, use the existing TAP flow separately from the employee passkey-registration paths. Passkey (FIDO2) registration isn't supported for internal or external guests; TAP support doesn't remove this restriction, and the current preview doesn't add an exception.
