Validate agent identitySecure a web API with Microsoft Entra ID

A downstream API must validate every access token before it trusts the Agent ID, user, or permissions represented by the token. Use a supported authentication middleware or token-validation library instead of parsing tokens in a downstream API

When an AI agent calls your API through the Microsoft Entra ID Auth SDK (sidecar), the request includes a Bearer token. Your API validates this token to confirm the request comes from an authenticated agent with the correct permissions. If validation fails, your API returns HTTP 401 with a reason.application code.

This article explainscovers Microsoft identity platform v2.0 access tokens.

The API registration must expose the delegated scope or application role that each endpoint requires, and the calling client or agent must have the corresponding grant. For an assembled local delegated test, follow Call a custom API as a user. For app-only caller setup and consent, follow Call a custom API as an agent.

Configure token validation

Configure the API with:

  • The Microsoft Entra tenant or accepted issuer set.
  • The API's Application ID URI or client ID as the expected audience.
  • Microsoft identity platform signing-key discovery.
  • The delegated scopes or application roles required by each operation.

For ASP.NET Core, use Microsoft.Identity.Web. For other frameworks, use a Microsoft-supported JWT validation checkslibrary.

For complete registration and shows howframework guidance, see Configure protected web API apps.

Configure an ASP.NET Core API

Install Microsoft.Identity.Web:

dotnet add package Microsoft.Identity.Web

Configure the tenant and API registration:

{
  "AzureAd": {
    "Instance": "https://login.microsoftonline.com/",
    "TenantId": "<tenant-id>",
    "ClientId": "<downstream-api-client-id>"
  }
}

Register token validation and protect delegated and app-only endpoints:

using Microsoft.Identity.Web;
using Microsoft.Identity.Web.Resource;

var builder = WebApplication.CreateBuilder(args);

builder.Services.AddMicrosoftIdentityWebApiAuthentication(
    builder.Configuration);

builder.Services.AddAuthorization(options =>
{
    options.AddPolicy(
        "AgentApplication",
        policy => policy.RequireRole("Agent.Access"));
});

var app = builder.Build();

app.UseAuthentication();
app.UseAuthorization();

app.MapGet("/data-for-user", (HttpContext context) =>
{
    context.VerifyUserHasAnyAcceptedScope("access_as_user");
    return Results.Ok();
})
.RequireAuthorization();

app.MapGet("/data-for-agent", () => Results.Ok())
    .RequireAuthorization("AgentApplication");

app.Run();

Replace access_as_user with the delegated scope exposed by the API. Replace Agent.Access with the application role assigned to configurethe Agent ID.

AddMicrosoftIdentityWebApiAuthentication validates the token signature, issuer, audience, and runlifetime. VerifyUserHasAnyAcceptedScope enforces the delegated scp claim. RequireRole enforces the application permission in the roles claim.

For more complete authorization patterns, see Verify scopes and app roles in a protected web API.

Test each endpoint with a token issued for this downstream API, not the agent's inbound token. With the required scope or role, the sample weatherreturns 200 OK. Without a token or with the wrong audience, expect 401. With an otherwise valid token for this API that validates agent identitylacks the required scope or role, expect rejection. How the sample weather API works

The Microsoft Entra Agent ID samples repository includes a sample weather API that demonstrates these validation checks. The sample API is a minimal Flask app that acts as the downstream API your agent calls. It validates incoming agent identity tokens and returns real weather data from Open-Meteo.

Both the local development (Ollama) and AWS (Bedrock) sidecar samples call the same weather API container. The sample consists of three files:

  • app.py: Flask app with route handlers, token validation logic, and Open-Meteo client.
  • Dockerfile: Uses python:3.13-slim as the base image. Runs gunicorn app:app on port 8080.
  • requirements.txt: Dependencies: flask, pyjwt[crypto], cryptography, requests, gunicorn.

The API exposes two endpoints:

  • GET /weather?city=<name>: Validates the Authorization: Bearer <token> header and returns weather data for the specified city.
  • GET /healthz: Returns a health status without requiring token validation.

The following diagram shows how tokens flow from the agent through the sidecar to the weather API. The agent never contacts Microsoft Entra ID directly. Instead, the sidecar acquires a token (TR) on behalf of the agent identity, and the agent passes that token to the weather API in the Authorization: Bearer header.

:::image type="content" source="media/how-to-validate-agent-tokens-downstream-api/agent-token-flow-to-downstream-api.png" alt-text="Diagram showing the agent caller sending a Bearer token to the weather API, which verifies the token and calls Open-Meteo." lightbox="media/how-to-validate-agent-tokens-downstream-api/agent-token-flow-to-downstream-api.png":::

The agent identity token, TR, is issued by Microsoft Entra ID through the sidecar. It contains the claims your API validates, including the xms_par_app_azp agent identity marker. For a detailed breakdown of all tokens in the flow, see Run the sidecar for local development.

Token validation libraries differ across ecosystems (Python, Node.js, .NET). This sample uses PyJWT with the cryptography backend for RS256 signature verification. When you build your own downstream API, choose the equivalent JWT validation library for your technology stack.

To run the weather API as a standalone container and test token validation:

  1. Clone the repository and navigate to the weather API directory:

    git clone https://github.com/microsoft/entra-agentid-samples.git
cd entra-agentid-samples/sidecar/weather-api

  2. Build and run the container:

    docker build -t weather-api:local .
docker run --rm -p 8080:8080 \
  -e TENANT_ID=<your-tenant-id> \
  -e EXPECTED_AUDIENCE=https://graph.microsoft.com \
  weather-api:local

  3. Send a request with an agent identity token:

    curl -H "Authorization: Bearer $TOKEN" \
     "http://localhost:8080/weather?city=Dallas"
