Overview

Enterprises

Remote onboarding users face significant challenges onboarding remotewith Microsoft Entra Verified ID uses government-issued, ID-based attestations to help establish trust with users who aren't yet inside theyour organization's trust boundary.

Choose between two onboarding patterns. If your organization uses Lifecycle Workflows in Microsoft Entra ID Governance, use the built-in identity-verification templates and tasks. If you have your own onboarding portal or solution and need to customize the experience, integrate with the Verified ID REST APIs.

Pattern 1: Built-in identity verification tasks with Lifecycle Workflows

Use this pattern to configure onboarding through the Pre-hire and New-hire identity-verification templates and tasks in Lifecycle Workflows, rather than implement the verification journey in a custom portal.

The pattern connects pre-hire identity verification with new-hire credential registration. An ID verification profile defines the verification journey, and the workflow uses that profile for its identity-verification tasks.

For this pattern, use an identity verification (IDV) partner offer with Security Store-based integration. The IDV partner gallery lists Security Store integration partners separately from Verified ID API-based integration partners. Review the relevant integration type when selecting a provider.

For configuration and the complete user journey, see Onboard users with identity verification (Preview). That guide covers:

  • Pre-hire and new-hire workflow configuration.
  • Inline passkey registration and the alternative that uses a Temporary Access Pass (TAP) with Conditional Access-protected registration.
  • Device, passkey-policy, and guest-account eligibility considerations.

Pattern 2: Custom onboarding portal with Verified ID REST APIs

Use this pattern if you have your own onboarding portal or solution and want to customize the experience by using Microsoft Entra Verified ID can help customers facing these scenariosREST APIs. Your application coordinates identity verification, credential presentation, user matching, and the remaining onboarding logic.

For this pattern, select a provider that supports Verified ID API-based integration from the IDV partner gallery, and follow that partner's integration guidance. Don't assume that a partner supports both integration types just because it can use government-issued, ID-based attestations asappears in the gallery.

Issues

The browser opens the invitation, and the onboarding portal validates the link before redirecting the new hire to the IDV partner. The new hire submits a selfie and documents through the browser. The partner portal creates an issuance request with an ID token hint. Microsoft Authenticator consumes the request, accepts the credential, and receives it from the Verified ID service.

The partner redirects the new hire to the onboarding portal. The new hire selects the presentation link, and the portal creates a presentation request with the Verified ID service. Microsoft Authenticator consumes the request, and the new hire consents to present the credential. The service returns the presentation response to the onboarding portal. The portal validates the user record against the credential claims through the HR system, calls Microsoft Graph to generate a TAP in Microsoft Entra ID, and presents the TAP to the new hire so onboarding can continue. :::image-end:::
