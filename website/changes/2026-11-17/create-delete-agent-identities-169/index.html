After you create an agent identity blueprint, the next step is to create one or more agent identities that represent AI agents in your tenant. Agent identity creation is typically performed when provisioning a new AI agent.

This procedure uses a multi-instance blueprint to provision child identities. If your blueprint uses single-instance mode, follow Create a single-instance agent identity instead. Its identity shares the blueprint's client ID and doesn't use the blueprint principal provisioning path below.

You can create agent identities in two ways:

  • Microsoft Entra admin center — Use the admin center wizard for quick, individual identity creation.
  • An agent identity blueprint. Record the agent identity blueprint app ID from the creation process.
  • A web service or application (running locally or deployed to Azure) that hosts the agent identity creation logic. This prerequisite applies only if you're creating agent identities programmatically.

Use the blueprint app ID as client_id in the token request. Save the agent identity id returned by the create call for the delete request. For identifier meanings, see Record the identifiers for your scenario.

Use the Microsoft Entra admin center

You can create an agent identity directly in the Microsoft Entra admin center by selecting an existing blueprint and assigning owners and sponsors. Always include the OData-Version header when using @odata.type.
