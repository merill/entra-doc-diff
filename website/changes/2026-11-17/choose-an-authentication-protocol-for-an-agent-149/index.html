The local agent is a public client. It sends the user to the Microsoft identity platform /authorize endpoint, receives an authorization code at its registered redirect URI, and redeems the code by using a PKCE verifier. It doesn't present a client credential.

A registered public-client Agent ID must use single-instance mode. Every installation uses the same client ID; don't create an Agent ID for each device. A local agent can alternatively use a Client ID Metadata Document (CIMD) URL as its client ID.

Don't use this flow for a hosted agent that receives a user access token from another application. Use OBO instead.

Autonomous agent that acts as a dedicated user

Choose agent's user account impersonation only when an autonomous agent needs capabilities that are available to a user but not to an application identity. For example, an agent might need its own mailbox.

An agent's user account is a dedicated user identity for the agent, not the account of the person using the agent. The Agent ID impersonates this account through an agent-specific token exchange. Access is limited by the permissions assigned to the Agent ID and the agent's user account.

Don't create an agent's user account only to run unattended work. If the resource supports application permissions, prefer app-only access so the workload doesn't depend on behalf of regular users (interactive agents)a user identity.
