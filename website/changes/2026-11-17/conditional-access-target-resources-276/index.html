Conditional Access: Target resources

17 November 2026New feature+24 / −1 lines

In brief

Documentation now describes the Account onboarding and recovery user action and a global exclusion for All resources policies. Administrators can apply a separate policy to onboarding and recovery, while noting that several controls and risk-based policies aren't supported for this action.

What Entra admins need to know

Review existing All resources policies and the tenant-wide exclusion setting so users can complete onboarding or account recovery, then protect those journeys with an appropriate user-action policy.

Conditional Access: Target resources

!Important

Microsoft recommends creating a baseline multifactor authentication policy targeting all users and all resources (without any resource exclusions), like the one explained in Require multifactor authentication for all users.

Exclude onboarding and recovery from All resources policies (preview)

Policies targeting All resources also apply to onboarding and account recovery events unless you enable the global user-action exclusion. These policies can require credentials or other controls that users can't satisfy before they establish or restore their authentication methods.

Under Entra ID > Conditional Access > Settings (Preview), Global exclusions exposes the Account onboarding and recovery (Preview) setting. When enabled, it excludes the Account onboarding and recovery user action from policies targeting All resources. Policies that directly target the user action still apply.

This is a global user-action exclusion, not a resource exclusion configured in an individual policy. It doesn't exclude users from ordinary application access policies. Review the tenant-wide impact and protect the bootstrap journey with a policy targeting the user action. For steps and validation guidance, see Enable the global onboarding and recovery exclusion.

Legacy Conditional Access behavior when an ALL resources policy has a resource exclusion

!Warning

User actions

User actions are tasks that a user performs. Conditional Access supports the following user actions:

  • Register security information: This user action lets Conditional Access policies enforce rules when users try to register their security information. For more information, see Combined security information registration.
!Warning

If a Conditional Access policy is configured with the Register or join devices user action, set Entra ID > Devices > Overview > Device Settings - Require Multifactor Authentication to register or join devices with Microsoft Entra to No. Otherwise, Conditional Access policies with this user action aren't properly enforced. Learn more about this device setting in Configure device settings.

Account onboarding and recovery (preview)

Use Account onboarding and recovery to apply Conditional Access to onboarding and recovery, separately from ordinary resource access. Before configuring an identity verification requirement, create an eligible identity verification profile. Follow Require identity verification with Conditional Access to configure and test the policy.

Creating a user-action policy doesn't automatically exclude the journey from All resources policies. To remove that overlap while retaining policies targeting the user action, enable the global onboarding and recovery exclusion.

!Note

Terms of use, Require authentication strength, and most other Microsoft Entra-specific controls aren't supported for this action. These limitations don't apply to ordinary resource-access policies. Review the control limitations before rollout. Don't use report-only results as proof that an onboarding or recovery policy is evaluated or enforced.

Risk-based Conditional Access policies currently don't apply to onboarding actions.

Authentication context

Authentication context secures data and actions in applications. These applications include custom applications, line-of-business (LOB) applications, SharePoint, or applications protected by Microsoft Defender for Cloud Apps. It can also be used with Microsoft Entra Privileged Identity Management (PIM) to enforce Conditional Access policies during role activation.
