Authentication and authorization

The credential management API acts on behalf of a signed-in customer.user. Every endpoint URL has the form https://{tenant-subdomain}.ciamlogin.com/{tenant-id}/api/v1.0/me/..., where {tenant-subdomain} is your external tenant's subdomain, {tenant-id} is your external tenant's ID, and me is the customeruser whose access token you send with the request. Your application:

  1. Signs the customeruser in.
  2. Obtains an access token for the credential management API.
  3. Includes that token on every call.

Without a signed-in customer,user, me has no meaning and the call can't be authenticated. If you've worked with Microsoft Graph or other Microsoft Entra REST APIs, this follows the same model: standard OAuth 2.0 with delegated permissions.

Include the access token in the standard HTTP Authorization header on every request:

Acquire a delegated access token

Use a delegated access token to call the credential management API on behalf of the signed-in customer.user. The API rejects app-only tokens, including tokens acquired through the client credentials flow. When the customeruser signs in, request one of the permissions listed in Required permissions. The requested permission determines the token audience; you don't set the audience separately.

Acquire the delegated token through the Microsoft Entra sign-in flow that applies to your application:

!Note

Access tokens acquired through native authentication are currently supported by this API only for web apps. Mobile apps can use MSAL's browser-based sign-in to acquire tokens to list authentication methods, delete passkeys, and update passwords.

Native passkey registration with Microsoft Entra External ID isn't currently supported on mobile platforms. Use the system browser to register passkeys.

Pass the resulting token as Authorization: Bearer <access_token> on every credential management API call.

Continuation token

When you call a multi-step operation such as registering a passkey or updating a password, the credential management API returns a continuation token in the response. This token uniquely identifies the current flow and lets Microsoft Entra maintain state across its endpoints. Include the most recently returned token in each subsequent request in that flow. It's valid only for a limited time and can only be used for the subsequent requests within the same flow. Don't reuse it for another user, credential method, or operation.

## Provisioning

Provisioning a passkey for the signed-in customeruser takes two HTTP calls. First, your application calls the begin registration endpoint, which returns WebAuthn creation options, a continuation token, and an `activate` link. The customeruser's authenticator uses the creation options to create a new passkey. Your application then calls the activate endpoint with the result to complete registration. Start this flow when the customeruser chooses to add a passkey in your application's credential-management experience.

## Delete a credential method

Permanently deletes one of the signed-in customeruser's registered passkeys. Use this endpoint after [listing the customeruser's credential methods](#list-user-credential-methods) and when the customeruser chooses to remove a passkey in your application's credential-management flow. Deletion is immediate and can't be undone. A replacement passkey is a new credential with no relation to the deleted passkey.
!Warning

If the user deletes the passkey they used to sign in to their current session, that session ends.

Update a password

This flow updates the signed-in user's existing password. Use this flow when the user knows their current password and chooses to change it in your application's credential-management experience.

This flow isn't a forgotten-password recovery flow. For password recovery in native authentication, see Self-service password reset.

Password updates require polling to confirm completion. The following flowchart shows the two-step update flow.

:::image type="content" source="media/reference-credential-management-api/update-password.png" alt-text="Flowchart that shows the user entering their current and new passwords, the app submitting the update, waiting for the polling interval, and polling with a continuation token to confirm completion." lightbox="media/reference-credential-management-api/update-password.png":::

{tenant-subdomain} in the URL is your external tenant's subdomain; for example, contoso in contoso.ciamlogin.com.
