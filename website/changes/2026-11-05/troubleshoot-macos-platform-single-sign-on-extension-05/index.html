Known issues

Authentication errors after locking or waking a Mac

On a Mac registered with Platform SSO, apps such as Microsoft Teams, Outlook, and Microsoft 365 Copilot might show sign-in errors after you wake or unlock the device. The error might include 4ut1e, -42008, or "Failed to sign the request". These errors aren't unique to this issue and can have other causes.

This issue can occur when an app requests a token before macOS unlocks the user's keybag, which protects cryptographic keys. Token decryption or request signing can fail while those keys are unavailable, and the resulting error can appear after you unlock the device.

Mitigation

If you're using an affected Mac, unlock the device and retry signing in. Contact your IT administrator if the issue recurs.

If you're an administrator managing devices with macOS 14 or later, enable Use Shared Device Keys in the Platform SSO configuration. This setting allows Platform SSO to access device authentication keys before the user unlocks the device and helps prevent this condition.

!Important

Changing Use Shared Device Keys in an existing deployment triggers device re-registration with Microsoft Entra ID. Plan the rollout and notify users before deploying the change.

  1. Edit the existing Platform SSO profile in your mobile device management (MDM) service. Under Platform SSO, set Use Shared Device Keys to Enabled. For Microsoft Intune, see Create the Platform SSO policy in Intune.

  2. Deploy the updated profile to the affected devices and have users complete the required re-registration.

  3. On an affected Mac, open the Terminal app and run the following command to check the effective configuration:

    app-sso platform -s

  4. Confirm that sharedDeviceKeys is true in the output.

If the issue persists with Shared Device Keys enabled in the effective configuration, collect Company Portal diagnostic logs and a sysdiagnose capture. Include the timestamps of the errors and follow the steps in Report an issue.

Unexpected/frequent re-registration prompts on macOS Sequoia

!Note

Because Secure Enclave keys are protected by your local account password, password resets that occur without providing this password (such as FileVault or MDM-based recovery) resets the Secure Enclave. Resetting the Secure Enclave renders keys previously stored for this account inaccessible. Devices whose Secure Enclave keys are lost must be reregistered to use Platform SSO.

Authentication errors after locking or waking a Mac

On a Mac registered with Platform SSO, apps might show sign-in errors such as 4ut1e, -42008, or "Failed to sign the request" after you wake or unlock the device. This can happen when token requests start before macOS unlocks the user's cryptographic keys, causing token decryption or request signing to fail. These errors can also have other causes.

On macOS 14 or later, enable Use Shared Device Keys in the Platform SSO configuration to help prevent this issue. This setting makes device authentication keys available before the user unlocks the device. For configuration details, see Configure Platform SSO in Intune. Changing this setting in an existing deployment triggers device re-registration with Microsoft Entra ID.

Report an issue

If you're experiencing issues with PSSO, you can report them on Company Portal.
