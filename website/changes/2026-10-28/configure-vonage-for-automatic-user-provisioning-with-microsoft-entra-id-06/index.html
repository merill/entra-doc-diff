Configure Vonage for automatic user provisioning with Microsoft Entra ID

28 October 2026RetirementAction required+51 / −29 lines

In brief

Vonage provisioning will stop supporting OAuth 2.0 Authorization Code Grant after March 31, 2027. The updated procedure generates and uses client credentials; SSO is unaffected.

What Entra admins need to know

Migrate affected provisioning jobs by March 31, 2027. Otherwise, user and group provisioning synchronization may stop, and existing jobs could eventually be removed.

This article describes the steps you need to perform in both Vonage and Microsoft Entra ID to configure automatic user provisioning. When configured, Microsoft Entra ID automatically provisions and de-provisions users and groups to Vonage using the Microsoft Entra provisioning service. For important details on what this service does, how it works, and frequently asked questions, see Automate user provisioning and deprovisioning to SaaS applications with Microsoft Entra ID.

!Important

To improve the security posture of application provisioning, Microsoft is retiring the OAuth 2.0 Authorization Code Grant for this application.

Migrate affected provisioning jobs to OAuth2 Client Credentials Grant by March 31, 2027, to avoid disruption to provisioning. After this date, provisioning jobs that continue to use Authorization Code Grant might stop working and could eventually be removed from the service.

This change doesn't affect SSO. Existing provisioned users can continue signing in, but new users won't be provisioned and changes to existing users and groups won't be synchronized while provisioning isn't functioning.

Follow the Vonage SCIM migration guide to migrate to OAuth2 Client Credentials Grant.

Capabilities Supported

[!div class="checklist"]

  • Create users in Vonage.
  • RemoveDeactivate users in Vonage when they don't require access anymore.
  • Keep user attributes synchronized between Microsoft Entra ID and Vonage.
  • Single sign-on to Vonage (recommended).
  • OAuth 2.0 Authorization Code Auth Grant flow authentication is supported until April 1, 2027. After this date, only OAuth 2.0 Client Credentials authentication is supported.

Prerequisites

  • A Microsoft Entra tenant.
  • One of the following roles: Application Administrator, Cloud Application Administrator, or Application Owner.
  • A Vonage tenant.
  • A user account in Vonage with Admin permission(Account Super User).permissions.

Step 1: Plan your provisioning deployment

  1. Log in to Vonage admin portal with an admin user.

  2. In the left navigation, select Account > User Provisioning. The Cross-Domain Identity Management (SCIM) settings page opens.

  3. Navigate toIn the Account > Single Sign-OnAuthentication Settings and Service Credentials on the left side menu.

  4. Select User Settings tab, toggle Enable SCIM user provisioning ON andsection, select SaveMicrosoft Entra as the identity provider. The Authentication Method dropdown is prepopulated with OAuth 2.0 Client Credentials.

!Note

When you change the credentials in Vonage, an existing provisioning job in Microsoft Entra ID may briefly continue using its current access token. These tokens typically expire one hour after they're issued and can't be refreshed after the credentials change in Vonage, which can cause temporary provisioning failures. Once you update the credentials in Microsoft Entra ID, subsequent sync cycles use the new credentials and retry failed provisioning operations. No additional action is needed for those failures.

  1. In the Ready to Generate Service Credentials dialog, select Continue.

  2. Enter one or more identity provider administrator email addresses, and select Generate Credentials.

  3. Copy the following values from the dialog and save them in a secure location, such as a password manager. Each value has an individual copy icon.

    Field Description
    Token Endpoint The token endpoint provided by Vonage.
    Tenant URL The tenant URL provided by Vonage.
    Client ID The automatically generated client ID.
    Client Secret ID The automatically generated client secret, which is visible only once.

  4. After you copy all four values, select Done to close the dialog.

!Warning

The Client Secret ID is permanently masked after you select Done. If you lose it, select Regenerate to generate a new secret.

[!INCLUDE monitor-deployment.md]Once you configure provisioning, use the following resources to monitor your deployment:

  1. Use the provisioning logs to determine which users are provisioned successfully or unsuccessfully.
  2. Check the progress bar to see the status of the provisioning cycle and how close it's to completion.
  3. If the provisioning configuration seems to be in an unhealthy state, the application goes into quarantine. Learn more about quarantine states in the application provisioning quarantine status article.
