[!INCLUDE applies-to-external-only]

By setting up federation with a custom-configured OpenID Connect (OIDC) identity provider, you enable users to sign up and sign in to your applications using their existing accounts from the federated external provider. This OIDC federation allows authentication with various providers that adhere to the OpenID Connect protocol. (Learn more about

After you configure an OIDC identity provider, there are two ways to enable users to authenticate with it:

  • Add the identity provider to a user flow: Adding the identity provider to a user flow displays a sign-in button on the sign-in page, allowing users to self-register and sign in. See Add an identity provider to a user flow.
  • Invite users: Have your application pass domain_hint in the authorization request to route invitation redemption to the configured OIDC provider. See Route invited users to an external identity provider.

For an overview of supported options, see Authentication methods and identity providers for customers.)

Prerequisites

  • An external tenant.
  • A registered application in the external tenant.
  • A sign-up and sign-in user flow. associated with your application.

Set up your OpenID Connect identity provider

  • OpenID Issuer URI: The entity of your identity provider that issues access tokens for your application. For example, if you use OpenID Connect to federate with your Azure AD B2C, your issuer URI looks like: https://login.b2clogin.com/{tenant}/v2.0/. The issuer URI is a case-sensitive URL that uses the https scheme. It contains scheme, host, and optionally port number and path components, but no query or fragment components.
!Note

For Microsoft Entra ID configuration details, see Add a Microsoft Entra ID tenant as an OpenID Connect identity provider. OIDC federation also isn't compatible with the Invite external user (preview) feature.Users who select this provider during self-service sign-up authenticate through custom OIDC. Invited users from another Microsoft Entra tenant use native Microsoft Entra federation by default, unless your application routes them to the custom OIDC provider with domain_hint.

  • Client ID and Client Secret are the identifiers your identity provider uses to identify the registered application service. Provide a client secret when you select a client_secret-based authentication method.
  • Client Authentication is the type of client authentication method to be used to authenticate with your identity provider using the token endpoint. client_secret_post and client_secret_jwt authentication methods are supported. Although the admin center UI might display private_key_jwt as an option, this method isn't currently supported and shouldn't be selected.
