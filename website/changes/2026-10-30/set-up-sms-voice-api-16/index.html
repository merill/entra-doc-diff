Set Up Sms Voice Api

30 October 2026Doc update+4 / −4 lines

In brief

The SMS/voice API setup documentation now links its rollout and diagnostic references to the choose-your-own-telephony troubleshooting page.

What Entra admins need to know

Administrators troubleshooting their own telephony provider will be directed to the relevant guidance; no action is required.

  1. Increase migrationPercentage in increments until you reach 100.
  2. Keep the endpoint URL, application client ID, and existing includeTargets unchanged while changing the migration percentage.
  3. Validate authentication and telecom provider delivery after each change.
  4. Increase the percentage after each stage validates successfully. To investigate an issue, hold at the current percentage and see Monitor and troubleshootMonitor and troubleshoot.
!Important

When each stage validates successfully, continue to 100 percent without delay. Completing your rollout early helps ensure uninterrupted authentication for your users. For dates, see Passkeys by default and retirement of Microsoft-provided SMS and voice authentication.

  1. In the Microsoft Entra admin center, go to Audit logs and filter by Service: Azure MFA. Open the latest entry and confirm Delivery Method is Cyot.
  2. In your provider's portal, confirm the message was delivered.

At a partial percentage, only some requests route through your provider, so make a few attempts. If something doesn't look right, see Monitor and troubleshoot your own telephony providerMonitor and troubleshoot your own telephony provider.

Troubleshooting

To diagnose integration issues, use the troubleshooting guide to identify whether the issue is with the Microsoft Entra configuration, Azure Function, telecom provider, or authentication flow.

See Monitor and troubleshoot your own telephony providerMonitor and troubleshoot your own telephony provider for diagnostic steps, logs, common issues, and remediation guidance.
