Validate an OIDC multitenant app for Microsoft Entra App Gallery onboarding

Before publishing your OpenID Connect (OIDC) multitenant application to the Microsoft Entra app gallery, you must validate that your sign-in implementation meets gallery requirements. Validation is a self-service step that confirms your app is ready to publishproduces a validation report and generates a Test ID required for submission.

The Microsoft Entra App Validator supports both single-tenant and multitenant OIDC applications. It evaluates your OIDC multitenant sign-in flow against Microsoft Entra app gallery requirements while you sign in to your application.

After validation, you'll have:

  • A validation report highlighting required and recommended fixes
  • A Test ID required to publish your app to the Microsoft Entra app gallery

The Microsoft Entra App Gallery SSO requirements define publication eligibility. Cloud SaaS applications must use a multitenant application. Single-tenant applications are acceptable when you deploy a separate application instance for each customer by using an infrastructure as a service (IaaS) or platform as a service (PaaS) architecture. Passing single-tenant validation doesn't automatically establish eligibility for App Gallery publication.

Prerequisites

Before starting validation, ensure the following are already true:

  • Your app is registered ashas a single-tenant or multitenant application registration in Microsoft Entra ID.ID that matches its architecture and the App Gallery eligibility requirements.
  • OIDC sign-in is implemented and working correctly.
  • Your app is deployed and accessible via a public URL.
  • Redirect URIs, scopes, and permissions are configured.
  1. Sign in to the extension using your Microsoft account.
  2. Select Start test.
  3. When prompted, confirm the starting page and select Yes, Start test.
  4. When the validator prompts you to select the OIDC tenant configuration, choose the configuration that matches the application architecture you intend to publish in the App Gallery:
    • Multitenant: For a cloud SaaS application that uses a shared application registration to serve customers across multiple Microsoft Entra tenants.
    • Single-tenant: For an application deployed as a separate instance for each customer using an IaaS or PaaS architecture.

The extension initializes the validation session and lists the checks it performs.

During authentication, the validator evaluates:

  • Microsoft sign-in entry point configuration
  • Tenant endpoint usage (for the selected configuration: /common or /organizations for multitenant apps)validation, or the tenant-specific OIDC configuration for single-tenant validation.
  • OIDC v2.0 endpoint compliance
  • Required scopes, including openid and profile
  • Authorization request structure and parameters
!Tip

Common validation failures include endpoints that don't match the selected tenant configuration, missing required scopes, and mismatched redirect URIs. A tenant-specific endpoint isn't a validation failure when you select Single-tenant. Both configurations must use Microsoft identity platform v2.0 endpoints. Resolve validation failures before publishing.
