Sms Voice Retirement Experience

23 November 2026Doc update+5 / −5 lines

In brief

The retirement guidance now points to the renamed telephony provider documentation page for setup and migration instructions.

What Entra admins need to know

Use the updated link when accessing telephony provider guidance.

This editorial summary was generated by AI from the documentation changes. Verify important details in the full Microsoft Learn article.

Documentation change

The comparison below shows only the changed extract. Use the full-page view for complete context.

Configuring a provider without completing user migration isn't sufficient. Test delivery and sign-in for the intended users before rollout.

For setup guidance, see Choose a telephony provider for SMS and voice authenticationChoose a telephony provider for SMS and voice authentication.

For users migrated to your telephony provider (CYOT), the usual SMS verification flow is unchanged. The following screens show the user entering their username and password, selecting Text on Verify your identity, and entering the text message code to complete sign-in. Call remains available as another verification option. This flow doesn't require the user to register a passkey because of retirement.

The method must be supported in the affected session, enabled for the user, and allowed by applicable Conditional Access policies and authentication strengths. Installing Microsoft Authenticator alone isn't enough; the user needs to complete the relevant registration and setup.

If SMS or voice is still required, configure a supported customer-managed telephony providercustomer-managed telephony provider and complete migration for the affected users. Before retirement, test the same browser and device combinations the users need. Customer-managed telephony provides a separate SMS or voice path; it doesn't add passkey support.

If a user reaches this screen, direct them to My Sign-Ins and have them use their existing SMS or voice registration to verify their identity and register another method. If they can't complete registration or still can't sign in, contact your support team. Don't tell them to skip registration or assume another SMS code allows them to continue to the application. Confirm the replacement method works with their actual session and access policies, not just their primary browser.

Customer-managed telephony for NPS

If SMS or voice is still required, configure a supported customer-managed telephony providercustomer-managed telephony provider for the affected users when available for your tenant. Complete migration and test the NPS-protected connections before retirement reaches your tenant.

Customer-managed telephony doesn't change the methods supported by the client. Validate the provider, deployment, and connection together rather than assuming every telephony option works with every NPS flow.

More restrictions can make registration more complicated. Make sure users have a device or authenticator that supports an allowed passkey type and can complete setup in their browser. The retirement prompt doesn't bypass those requirements. If no allowed passkey can be registered on the current device, the user sees the retirement guidance shown in Scenario 6.

If affected users can't complete registration and need immediate sign-in relief, configure a supported telephony provider (CYOT)telephony provider (CYOT) and complete their migration. This restores SMS or voice sign-in for those migrated users in supported scenarios.
