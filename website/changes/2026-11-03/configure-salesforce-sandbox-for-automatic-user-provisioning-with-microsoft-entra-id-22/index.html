Configure Salesforce Sandbox for automatic user provisioning with Microsoft Entra ID

In brief

The tutorial adds requirements to enable SOAP API `login()` and grant the integration account API Enabled, Manage Users, and Use Any API Auth permissions. It also documents Salesforce’s December 1, 2026 requirement for Use Any API Auth and related credential errors.

What Entra admins need to know

Enable SOAP API `login()` and configure the integration account permissions to prevent Test Connection and provisioning failures.

Configure Salesforce Sandbox for automatic user provisioning with Microsoft Entra ID

  • A Microsoft Entra tenant.
  • A valid tenant for Salesforce Sandbox for Work or Salesforce Sandbox for Education. You may use a free trial account for either service.
  • A user account in Salesforce Sandbox with Team Admin permissions.
  • SOAP API login() enabled in your Salesforce Sandbox org. Salesforce disables this operation by default for orgs created in Winter '26 and later. In Salesforce Setup, enter User Interface in the Quick Find box, select User Interface, and select Enable SOAP API login(). This action can't be reverted on the User Interface page. For details, see the Salesforce SOAP API login() reference.
  • A profile for the integration account entered in Admin Username with API Enabled, Manage Users, and Use Any API Auth enabled.

The Admin Username account needs Use Any API Auth because the Microsoft Entra provisioning service signs in through SOAP API login(). Salesforce's Winter '27 release update requires this permission for SOAP API sign-ins in all orgs, including sandboxes, from December 1, 2026. For details, see Assign Use Any API Auth Permission for SOAP login().

Common issues

  • If Test Connection fails, verify that SOAP API login() is enabled in the Salesforce Sandbox org and that the Admin Username account has Use Any API Auth.
  • SalesforceCredentialValidation: If Test Connection reports "Your Salesforce.com credentials are invalid..." even with a correct password and a fresh security token, check the integration account's Use Any API Auth permission. Salesforce Login History can show successful sign-ins even when this connection fails. If the underlying error is INSUFFICIENT_ACCESS: SOAP API login() requires the Use Any API Auth user permission, grant Use Any API Auth to the integration account's profile, and then retry Test Connection.
