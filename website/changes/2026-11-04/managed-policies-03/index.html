Conditional Access

Managed Policies

4 November 2026Feature update+3 / −2 lines

In brief

The policy now names its security group, excludes tenants with an enabled customer-managed user-risk policy, and automatically enables itself on the communicated schedule if left in Report-only.

What Entra admins need to know

Administrators should review the policy and its security group before scheduled enforcement; no mandatory action is stated.

Require remediation for high-risk users

This policy requires users identified as high risk by Microsoft Entra ID Protection to remediate their risk before continuing to access organizational resources. A new security group named “Conditional Access: User Risk remediation” is created alongside this policy to scope the affected users. Microsoft populates this group with eligible active users registered for MFA, up to the tenant’s available Microsoft Entra ID P2 license count. Instead of blocking access entirely, this policy uses adaptive risk remediation to guide users through the appropriate recovery flow based on their authentication method and the type of threat detected. For more information about the remediation experience, see User self-remediation with Microsoft Entra ID Protection.

!Note

Hybrid tenants: Eligible tenants have password hash sync enabled, so affected users can self-remediate through a secure password change after completing MFA. Ensure your users are registered for MFA. For more information, see Considerations for cloud and hybrid users.

This policy targets:

  • Organizations with Microsoft Entra ID P2 licenses
  • Organizations that don't already have an enabled customer-managed Conditional Access policy targeting user risk. Microsoft skips tenants that already have an enabled customer-managed Conditional Access policy targeting user risk. Existing user risk policies in Report-only or Off state don't prevent this Microsoft-managed policy from being created. This check is specific to user risk policies, not all Conditional Access policies.

Key considerations:

  • Authentication strength and sign-in frequency (every time) are automatically applied to ensure users reauthenticate with the required strength after session revocation.
  • This policy isn't supported for external and guest users.

Administrators can review policy impact in report-only mode, exclude emergency access accounts, and moveturn the policy On before the scheduled enforcement date. If the policy remains in Report-only, Microsoft automatically enables it according to On when ready.the schedule communicated to your tenant.
