Week in brief

PIM Iteration 2 API retirement and eDiscovery access enforcement are the week’s consequential changes

The week of 27 October 2025 was dominated by documentation maintenance: 121 items were updated, with no new or removed items recorded. The two Message Center notices carry the clearest operational impact. Microsoft Entra Privileged Identity Management (PIM) Iteration 2 beta APIs now have a retirement date, while Microsoft Purview is applying Entra Conditional Access compliance to eDiscovery administrators’ SharePoint access. Other notable updates clarify existing behavior or describe capabilities explicitly marked as preview; they do not establish a new GA launch on the supplied evidence.

  • ID Governance · Fundamentals
    PIM Iteration 2 beta APIs will be retired on 28 October 2026

    Retirement notice for Microsoft Entra Privileged Identity Management. Applications that continue using the Iteration 2 beta APIs will fail after the retirement date. Microsoft directs organizations to migrate to the more reliable Iteration 3 APIs, identified as GA, and to stop new development on Iteration 2.

  • ID Protection · Conditional Access
    Purview eDiscovery access will enforce Entra Conditional Access compliance

    This is a Message Center change in enforcement behavior, not a documentation-only edit. During a rollout that begins in this period and completes by November 2025, non-compliant eDiscovery administrators will be blocked from accessing SharePoint content under Microsoft Purview’s enforcement of Entra Conditional Access policies. The change also adds a FilePreviewed audit log activity for compliance monitoring.

  • Entra ID · Conditional Access
    Conditional Access optimization agent documentation clarifies scope and required roles

    The updated guidance describes an agent that can explain or reorder policy suggestions through natural-language chat, evaluate MFA and device-based controls, identify legacy authentication and device code flow exposure, propose consolidation of similar enabled policies, and offer one-click remediation. To produce Intune device-compliance or app-protection suggestions, it must run as a Global Administrator or as a Conditional Access Administrator together with Global Reader; Conditional Access Administrator alone is

  • Entra ID · Authentication
    External authentication method guidance documents a double-redirect outcome

    This is an authentication behavior clarification. The guidance says to use a test group for each policy, but not the same users in both. A user included in both policies—or affected by a policy containing both conditions—must satisfy MFA and the custom control, causing a second redirect to the external provider.

  • ID Governance · Governance
    Lifecycle Workflows updates describe two explicitly preview capabilities

    The updated ID Governance documentation describes Custom Attribute Triggers as an attribute-change trigger within a Lifecycle Workflow. It also describes delegated workflow management in preview, using Administrative Units to limit specific administrators to managing specific workflows instead of granting broad workflow-management access. These updates describe preview functionality and do not, by themselves, establish a new launch or GA status.

For Entra administrators

Inventory applications that use PIM Iteration 2 beta APIs, stop new development on them, and plan migration to the Iteration 3 GA APIs before 28 October 2026. Review the Conditional Access requirements affecting eDiscovery administrators and account for the new FilePreviewed audit activity. Administrators using the Conditional Access optimization agent or external authentication methods should apply the clarified role and test-group guidance. The Lifecycle Workflows changes remain preview documentation rather than evidence of a tenant-wide rollout.

Updated

There might be situations while configuring or managing an application where you don't want tokens to be issued for an application. Or, you might want to block an application that you don't want your employees to try to access, like the deprecated Azure AD PowerShell modules (AppID 1b730954-1685-4b74-9bfd-dac224a7b894). The Conditional Access optimization agent evaluates policies such as requiring multifactor authentication (MFA), enforcing device based controls (device compliance, app protection policies, and domain-joined devices), and blocking legacy authentication and device code flow. When the agent identifies a suggestion, you can have the agent update the associated policy with one click-remediation.

Delegated workflow management (preview)

Updated

Workflows by default, unless specified during creation, are managed by users with either the Lifecycle Workflows, or Global, administrator roles. As workflows grow and change to meet the needs of members of your organization, so does the need to limit who can manage them. With delegated workflow management, you can scope management of workflows using [Administrative Units](../identity/role-based-access-control/administrative-units.md). When scoped, specific admins are only granted access to manage specific workflows. Scoping allows for greater security within your environment by following Microsoft's least privileged access guidelines by only giving access to specifically what's needed.
