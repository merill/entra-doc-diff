Week in brief

Global Secure Access previews managed TLS certificates and custom HTTP headers

The week’s most consequential Entra administrator content centers on two Global Secure Access preview workflows: Microsoft-managed root certificates for TLS inspection and custom HTTP headers through Web Content Filtering v2. Most other changes are documentation-focused, but several carry operational weight: Cloud Sync now states exact group-membership prerequisites, the Entra SOC Identity Responder’s containment permissions are spelled out, and Workload ID guidance sets a 98% quota threshold for creating or recreating managed identities. Authentication guidance also says registration-campaign rollout continues through September 2026.

  • Global Secure Access · Security
    Microsoft-managed root CA path documented for Global Secure Access TLS inspection

    New guidance describes a preview option that creates a tenant-specific Microsoft-managed root CA for Microsoft Entra Internet Access TLS inspection. Administrators must deploy the public certificate to client devices before enabling inspection to avoid certificate errors; Microsoft protects the private key.

  • Global Secure Access · General
    Custom HTTP headers get a Web Content Filtering v2 preview workflow

    New preview guidance describes adding custom HTTP headers to matching outbound web requests through Web Content Filtering v2 rules, including tenant restrictions and other header-aware services. TLS inspection and the documented Global Secure Access prerequisites are required.

  • Entra ID · Provisioning
    Cloud Sync topology guidance sets explicit group membership requirements

    The updated guidance states that cloud-synced groups can contain only on-premises synchronized users and additional cloud-created security groups, and that all users must have `onPremisesObjectIdentifier`. Administrators should review group provisioning designs against these documented requirements.

  • Entra ID · General
    Entra SOC Identity Responder permissions now include containment actions

    The updated permissions reference documents identity-containment actions for the Entra SOC Identity Responder role, including disabling users, revoking active sign-in sessions, and resetting passwords. The role should be considered when delegating SOC incident-response tasks.

  • Workload ID · General
    Workload ID guidance sets a 98% directory-quota creation block

    The managed identities FAQ now states that creating a managed identity is blocked when resulting directory usage reaches or exceeds 98% of the tenant quota. The limit applies to new or recreated service principals; existing identities and assignments continue to work, and soft-deleted objects count toward usage.

For Entra administrators

Evaluate the Global Secure Access previews against their prerequisites; for Microsoft-managed TLS inspection, deploy the public root certificate to client devices before enabling inspection. Review Cloud Sync group designs and SOC role assignments, and monitor directory usage before creating or recreating managed identities. No mandatory action or deadline is stated for the registration-campaign documentation update.
