Week in brief

SSPR reset verification changes on 7 September; Excel 2021 has a 24 July authentication deadline

The week of 22 June 2026 was dominated by Microsoft Learn maintenance—353 updates, 17 new pages, and no removals—rather than evidence of a broad Entra feature launch. The material administrator-facing exceptions are concrete: Self-Service Password Reset (SSPR) will require explicitly registered authentication methods from 7 September; older Excel 2021 clients face a 24 July deadline to retain Power Query Organizational Account authentication; and Teams for the web is beginning to honor Microsoft Entra Keep Me Signed In settings. New tenant-recoverability guidance and Global Secure Access automation samples are meaningful security and operations additions, but the supplied records do not establish GA status or a service rollout for them. A separate Conditional Access notice flags improved enforcement for policies with resource exclusions but provides no timing or technical detail.

  • Entra ID · Authentication
    Changed behavior: SSPR will require explicitly registered methods

    The 27 June Microsoft 365 Message Center major update says that, beginning 7 September 2026, SSPR password-reset verification will require authentication methods explicitly registered by users. Directory-sourced contact information will no longer suffice unless it is registered. A registration campaign begins 6 August.   • Entra ID · Authentication
    Client compatibility change: Excel 2021 Power Query authentication has a 24 July deadline

    The 25 June notice says Excel Power Query is changing its Organizational Accounts authentication flow for Microsoft Entra ID. Excel 2021 version 21.08 or older must be updated to build 16.0.14334.20754 or later by 24 July 2026, or upgraded to a newer Excel version, to avoid authentication loss. Microsoft 365 and newer Excel versions are stated to be unaffected. This is a client update dependency, not a tenant-side Entra feature launch.

  • Entra ID · Conditional Access
    Changed behavior: Teams for the web will respect Entra KMSI

    The 26 June notice says Teams for the web will respect Microsoft Entra ID Keep Me Signed In settings starting in late June 2026. A session persists only when the user chooses to stay signed in; otherwise, the session clears when the browser closes. Microsoft explicitly says no immediate action is required. The practical change is in session persistence, particularly on shared devices.

  • Entra ID · Conditional Access
    Upcoming Conditional Access enforcement change has insufficient detail for remediation

    The 23 June Message Center entry flags an upcoming change described as improved enforcement for Conditional Access policies with resource exclusions. The supplied record includes no effective date, affected resource types, or before-and-after enforcement semantics. It is a watch item, but this evidence does not support a specific policy edit or impact assessment.

  • Global Secure Access · General
    Security and resilience documentation expands for recovery and Global Secure Access operations

    A new Plan for tenant recoverability page covers tenant-scoped recovery under the shared responsibility model. Related updates address deletion impact, supported objects and attributes, object recovery, and difference reports; the documentation says Backup Reader can review difference reports, while Backup Administrator can review and create them, and Global Administrator includes those permissions. The updated application-secret recovery page is explicitly labeled Preview. New Global Secure Access PowerShell pages

For Entra administrators

Use the SSPR registration campaign beginning 6 August to prepare users for the September verification change, and inventory Excel 2021 version 21.08-or-earlier installations for the specified build or upgrade path. The Excel notice says Microsoft 365 and newer Excel versions are unaffected. Teams requires no immediate action according to the notice, although browser-close session behavior will change on shared devices. For the recovery and Global Secure Access material, treat the pages as guidance and automation examples rather than proof of a new or generally available capability. The Conditional Access record is too terse to support a policy change or precise remediation; no effective date or before-and-after behavior is supplied.
