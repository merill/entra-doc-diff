Week in brief

Passkey campaigns accelerate registration as External ID moves customer credential management to Graph

The consequential items were a passkey-registration rollout and a change in the documented path for customer passkey management. Entra ID’s optimized registration campaign begins rolling out in early September 2026, while External ID guidance now points to Microsoft Graph FIDO2 provisioning APIs. A new Verified ID setup page adds concrete prerequisites and limits; other notable updates move My Staff control to role and administrative-unit scope and revise a device-code policy selection path. Most remaining changes were naming, link, and legacy-setting cleanup.

  • Entra ID · Authentication
    Optimized passkey registration campaigns begin rolling out

    Microsoft says the enhanced campaign rollout begins in early September 2026. Eligible users will be automatically prompted based on qualifying passkey profiles, so administrators should review campaign configurations and user assignments before rollout.

  • External ID · Authentication
    External ID passkey guidance switches applications to Graph APIs

    The Sign In With Passkey guidance no longer directs applications to the preview credential management API. It now recommends Microsoft Graph FIDO2 provisioning APIs and says low-privilege passkey credential-management APIs are on the roadmap.

  • External ID · Security
    New Verified ID article documents setup prerequisites and limits

    The new setup path covers Quick setup, application registration, credential creation, and credential issuance and verification in an External ID tenant. It documents custom-domain requirements, shared signing keys, a two-requests-per-second-per-tenant limit, six-month credential validity, and required roles.

  • Entra ID · General
    My Staff access guidance shifts to roles and administrative units

    The updated guidance says My Staff access is determined by administrative role assignments and their administrative-unit scope. Legacy settings under Manage user feature settings no longer affect behavior and are being removed from the admin center.

  • Entra ID · Monitoring
    Device Registration Service exclusion instructions use a new path

    The device-code-flow policy guide now directs administrators through Exclude > Select resources > Select specific resources before adding Device Registration Service. The exclusion is required to prevent device registration through device code flow from being blocked.

For Entra administrators

Review passkey campaign configurations and user assignments before rollout, and use Microsoft Graph FIDO2 provisioning APIs for customer passkey management. For Verified ID, account for custom-domain requirements, shared signing keys, a two-requests-per-second-per-tenant limit, and six-month credential validity. Use role assignments and administrative-unit scoping for My Staff, and follow the revised resource-selection path when excluding Device Registration Service from device code flow policies.
