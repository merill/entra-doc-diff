Week in brief

Entra MFA now prioritizes non-telephony methods ahead of SMS and voice

The period’s consequential changes center on MFA behavior, provisioning deadlines, passkey registration, and synchronization safeguards. MFA flows now put non-telephony methods first; GoTo provisioning requires an OAuth migration; and My Sign-ins is receiving a revised passkey-registration journey. Other notable guidance documents cross-tenant synchronization behavior and Conditional Access Policy Plan limits, while many remaining edits are terminology, navigation, or link updates.

  • Entra ID · Authentication
    MFA flows put non-telephony verification methods first

    Microsoft Entra ID now prioritizes more secure non-telephony methods over SMS and voice. Users can still select SMS or voice through “Show more verification methods,” but should expect a resend waiting period. The rollout occurs in October 2026, and SMS and voice are planned for retirement in February 2027; no configuration change is required for this rollout.

  • Entra ID · Provisioning
    GoTo provisioning must move from Authorization Code Grant

    The GoTo automatic-provisioning tutorial now directs administrators to create an OAuth client and configure Client Credentials Grant because Authorization Code Grant is being retired. Migration is required by March 31, 2027; otherwise user and group synchronization may stop, while single sign-on remains unaffected.

  • Entra ID · Authentication
    My Sign-ins adds guided passkey registration for Authenticator users

    The updated Microsoft Entra passkey-registration experience adds a checkbox, revised link text, and guided steps to start registration. If direct registration fails, users are directed to the WebAuthn flow. Rollout runs from mid-November 2026 through the end of November 2027, and administrators are asked to inform users.

  • Entra ID · Provisioning
    Cross-tenant sync restarts can leave out-of-scope users behind

    If a user is removed from a cross-tenant synchronization job’s scope and the job is restarted before the next synchronization cycle, the user is not deleted from the target tenant. Administrators should wait for the next synchronization cycle before restarting the job.

  • Entra ID · Conditional Access
    Conditional Access Policy Plans document explicit scaling limits

    Each Conditional Access Policy Plan supports up to 100 rules, and each tenant supports up to 100 plans. The guidance also streamlines scenarios involving Global Secure Access and agent access.

For Entra administrators

Prepare users for the MFA and passkey experience changes. Inventory GoTo provisioning connections and migrate from Authorization Code Grant by March 31, 2027. When removing users from cross-tenant synchronization scope, wait for the next synchronization cycle before restarting the job. Use the documented 100-rule and 100-plan limits when designing policy plans. No configuration change is required for the MFA method-ordering rollout.
