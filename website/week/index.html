Week in brief

System-preferred first-factor rollout precedes Entra’s myaccount.cloud.microsoft domain shift

Microsoft Entra is applying system-preferred authentication to first-factor sign-ins for tenants in the Microsoft managed state through late September 2026, while My Account and related self-service identity experiences are scheduled to move worldwide to myaccount.cloud.microsoft in late November. Global Secure Access guidance adds immediate version-upgrade requirements and a Windows Update upgrade path beginning in November. Microsoft Single Sign-on for Linux version 2.0.2 also changes device-trust handling, while enhanced synchronization adds a configurable source for hybrid sAMAccountName values. Much of the remaining activity consists of example-ID, link, and wording maintenance.

  • Entra ID · Authentication
    First-factor sign-ins now use system-preferred authentication in managed tenants

    For tenants in the Microsoft managed state, system-preferred authentication selects the most secure registered method for first-factor sign-ins. Rollout runs from late June through late September 2026; tenants can keep or change the setting and should update user guidance accordingly.

  • Entra ID · General
    My Account self-service moves to myaccount.cloud.microsoft worldwide

    Microsoft plans a worldwide rollout in late November 2026, changing the self-service identity-management domain from myaccount.microsoft.com to myaccount.cloud.microsoft and consolidating related sites. Users need no action, but administrators should allow *.cloud.microsoft in network policies.

  • Global Secure Access · General
    Global Secure Access deprecates four older client versions

    The version history marks 1.5.612.0, 1.5.402.0, 1.5.132.0, and 1.5.36.0 as deprecated. Users running version 1.5.612.0 or earlier are instructed to update immediately to retain fully supported features.

  • Entra ID · General
    Linux broker 2.0.2 switches device trust to Entra join

    Starting with Microsoft Single Sign-on for Linux broker version 2.0.2, device trust uses Microsoft Entra join instead of device registration. Existing upgraded devices must be re-joined and re-enrolled; upgrade procedures should remove broker state, reinstall the broker, and re-join the devices.

  • Entra ID · Security
    Enhanced synchronization can source sAMAccountName for hybrid users

    Enhanced synchronization can source hybrid users’ sAMAccountName from onPremisesSamAccountName. Existing domains retain current behavior until the setting is enabled, after which existing hybrid users are updated during synchronization. The setting applies to Enterprise or Premium managed domains and requires the documented administrator roles.

For Entra administrators

Review system-preferred authentication settings and user guidance in Microsoft-managed-state tenants. Ensure *.cloud.microsoft is permitted by network policies before the November domain rollout. Update Global Secure Access deployments running version 1.5.612.0 or earlier immediately, and decide whether eligible Windows clients should receive automatic upgrades through Windows Update. Plan Linux broker 2.0.2 upgrades for device rejoin and re-enrollment, and review source data and application dependencies before enabling sAMAccountName synchronization.
