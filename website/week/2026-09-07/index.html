Week in brief

User.ReadBasic.All loses app-role and license access as Entra automates passkey prompts

Two administrator-facing changes stand out. Microsoft Graph will narrow User.ReadBasic.All from mid-September 2026, requiring affected applications to use User.Read.All or LicenseAssignment.Read.All for the removed data. At the same time, optimized Entra passkey registration campaigns will automatically prompt eligible users based on qualifying passkey profiles as rollout starts in early September. The period also carries a Global Secure Access Internet Access and Purview DLP milestone plus two new External ID implementation guides. Most remaining entries are lower-action documentation maintenance, including link consolidation, Copilot renaming, and legacy My Staff references.

  • Entra ID · Microsoft identity platform
    User.ReadBasic.All will lose two data-access paths

    Starting mid-September 2026, User.ReadBasic.All will no longer allow applications to read user app role assignments or license details. Applications that need this data must move to User.Read.All or LicenseAssignment.Read.All to avoid disruption; Microsoft says the change addresses a security issue.

  • Entra ID · Authentication
    Passkey campaigns will automatically prompt qualifying users

    Entra’s optimized passkey registration campaign experience automatically prompts eligible users based on qualifying passkey profiles. Rollout begins in early September 2026; administrators should review campaign configurations and user assignments before rollout.

  • Internet Access · Conditional Access
    Purview DLP extends Internet Access filtering to sensitive files

    Microsoft Purview DLP integrates with Entra Global Secure Access Internet Access to filter sensitive files at the network layer and prevent leaks to unmanaged cloud apps. The Message Center notice lists general availability by October 2026; using it requires policy configuration, TLS inspection, and Purview pay-as-you-go activation.

  • External ID · Authentication
    External ID adds a unified identity-provider user-flow procedure

    A new External ID article covers adding configured OIDC, SAML/WS-Fed, or social identity providers to a user flow, including prerequisites, permissions, portal steps, and testing. It provides one central procedure for making those providers available on self-service sign-up pages.

  • External ID · Security
    Verified ID guidance records tenant limits and prerequisites

    A new External ID article documents Quick setup, app registration, credential creation, and issuing and verifying credentials. It also records custom-domain requirements, shared signing keys, a two-requests-per-second-per-tenant limit, and six-month credential validity for implementation planning.

For Entra administrators

Prioritize application inventory and permission updates before the mid-September Graph change. Review passkey campaign configurations and user assignments before rollout. If adopting Purview DLP through Internet Access, plan for policy configuration, TLS inspection, and Purview pay-as-you-go activation. For External ID work, use the new guides to check prerequisites, permissions, and stated tenant limits before implementation.
