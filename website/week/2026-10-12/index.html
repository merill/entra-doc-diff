Week in brief

Microsoft Entra changes agent blueprint access and identity-creation consent in November

The week’s clearest operational shift is in Agent ID: from November 4, default users may create agent blueprints unless administrators turn off the setting, while agent identity creation will require explicit admin consent. Microsoft is also rolling out secure-sign-in password changes, creating a Microsoft-managed high-risk remediation policy, and expanding PIM role-activation preview guidance with asynchronous postapproval checks.

  • Agent ID · Microsoft identity platform
    Default users will be able to create agent blueprints

    Starting November 4, 2026, default Microsoft Entra users can create agent blueprints unless Users can create agent blueprints is set to No. Setting it to No limits creation to administrators and the Agent ID Developer and Agent ID Administrator roles; rollout completes in late November.

  • Agent ID · Authentication
    Admin consent becomes mandatory for AgentIdentity.CreateAsManager

    Starting November 4, Microsoft Entra will stop automatically granting the AgentIdentity.CreateAsManager permission to agent blueprints. Agents will require admin consent to create identities, with worldwide rollout during November 2026.

  • Entra ID · Authentication
    Strong sign-in can precede password changes without the current password

    Microsoft Entra will let users change passwords after secure sign-in with a passkey, FIDO2 security key, or Windows Hello for Business, without knowing the current password or using SSPR. The feature is disabled by default, requires administrator activation, and rolls out globally from October through November 2026.

  • ID Protection · Conditional Access
    A Microsoft-managed CA policy targets high-risk users

    Microsoft created Require risk remediation for high-risk users along with a new security group. The policy uses Microsoft Entra ID Protection to identify high-risk users and prompts them to self-remediate through adaptive risk remediation; the message says enforcement is imminent.

  • ID Governance · Governance
    PIM activation preview adds deferred postapproval validation

    Updated guidance adds postapproval extensions with deferred outcomes and asynchronous validation before assignment provisioning. Administrators can collect attributes such as cost center and project code, but must configure the required Microsoft Graph permissions and endpoint; the capability requires an Entra ID Governance or Entra Suite license.

For Entra administrators

Review the Users can create agent blueprints setting and decide whether to set it to No before the late-November rollout. Prepare for admin consent on AgentIdentity.CreateAsManager, and activate the password-change feature only if desired. Account for the new high-risk remediation policy and group, while noting that PIM custom extensions require Entra ID Governance or Entra Suite; Entra ID P2 alone is insufficient.
