Day in brief

Risk-based CAPTCHA expands Entra sign-in defenses as Cloud Sync guidance tightens prerequisites

Microsoft is rolling out risk-based CAPTCHA for SMS and voice first-factor sign-ins to curb automated abuse; the rollout began in mid-October and prompts depend on user behavior. The most actionable documentation updates make Cloud Sync enforcement prerequisites explicit, define the scope and limits of passwordless cloud-password changes, and clarify how Global Secure Access V2’s Continue action moves traffic across profiles. A new Agent ID tutorial covers PostgreSQL access for agents, while Authenticator usability improvements are scheduled from November 2026.

  • Entra ID · Authentication
    Risk-based CAPTCHA reaches SMS and voice first-factor sign-ins

    Microsoft Entra ID is adding risk-based CAPTCHA verification to SMS and voice first-factor sign-ins to reduce automated abuse. Rollout began in mid-October 2026, and users may see the challenge based on their behavior. Organizations should prepare help desks, review network requirements, and encourage phishing-resistant methods such as passkeys.

  • Entra ID · Provisioning
    Cloud Sync enforcement now has explicit domain-controller and tool prerequisites

    The updated guidance requires every writable domain controller to meet the specified Windows Server update levels and requires ADSyncTools version 2.6.0 or later. It warns that enforcement cannot be configured if any writable domain controller is unsupported.

  • Entra ID · Authentication
    Passwordless SSPR guidance defines a tenant-wide secure sign-in setting

    The updated SSPR deep dive documents cloud-password changes after authentication with a FIDO2 passkey or Windows Hello for Business credential, without the current password. It identifies a tenant-wide setting required to enable the experience, says it cannot be scoped to groups, and calls out a limitation involving on-premises password writeback.

  • Internet Access · Fundamentals
    Global Secure Access V2 clarifies Continue’s cross-profile evaluation

    The web-filtering guidance now describes Continue as a preview default action when no enabled enforcement rule matches. Continue passes evaluation to the next applicable security profile in priority order, while Allow and Block stop V2 evaluation; the examples also distinguish Baseline and V1 behavior.

  • Agent ID · Conditional Access
    New Agent ID tutorial covers PostgreSQL authorization for agents

    A new tutorial explains how to configure Microsoft Entra agent identities to authenticate to Azure Database for PostgreSQL flexible server and access data through group-based authorization, entitlement management, and Conditional Access. It covers prerequisites, Entra authentication, security groups, token exchange, and database permissions.

New
