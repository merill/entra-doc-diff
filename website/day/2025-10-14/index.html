Day in brief

Teams Entra authentication rollout is the consequential change; most other updates refine deployment guidance

On 14 October 2025, Microsoft Entra had one service-impacting Message Center notice alongside 11 documentation updates, with no new or removed items recorded. Microsoft Teams group-chat agents and bots are scheduled to support Entra authentication during November 3–6, 2025. The other meaningful changes are documentation guidance for passwordless authentication, native-authentication CORS architecture, and group provisioning back to AD DS.

  • Entra ID · Authentication
    Teams group-chat agents and bots are scheduled to gain Entra authentication

    The Message Center notice says support begins November 3–6, 2025. The capability is enabled by default and requires no admin action; users without the Teams app or Entra consent will receive a private prompt to install the app and grant permissions.

  • Entra ID · Authentication
    Password-removal guidance was updated for passwordless and phishing-resistant authentication

    The updated Remove Passwords from Microsoft Entra ID page provides guidance for deploying passwordless and phishing-resistant authentication. This is security guidance and documentation, not evidence of a new authentication capability, retirement, or required tenant setting.

  • Entra ID · Authentication
    Native Authentication production guidance recommends Azure Front Door for CORS

    The updated production-environment guidance recommends Azure Front Door with a Standard/Premium subscription as a reverse proxy for the native authentication CORS solution. The record describes an architectural recommendation; it does not establish that Front Door is mandatory or that native authentication availability changed.

  • Entra ID · Provisioning
    Group writeback guidance calls out OU-path preservation

    For groups provisioned back to AD DS, the updated instructions say to preserve the OU Path and set it in the Group Provision to AD configuration with the correct mapping. Administrators using this provisioning scenario should review their mapping against the guidance; no broader provisioning behavior change is stated.
