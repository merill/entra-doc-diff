Day in brief

2 July 2025 was documentation-heavy: explicit Entra DNS redirection guidance led the day, with Conditional Access and troubleshooting clarifications—not a feature rollout.

All 20 supplied records are Microsoft Learn updates. There are no new or removed records and no Message Center notices. The meaningful edits are guidance and reference changes: the Manage DNS page warns against zone-level redirection for windowsazure.com and core.windows.net; Conditional Access documentation clarifies log interpretation; Graph troubleshooting calls out email-validation sign-up failures; and Global Secure Access documents an application-discovery workflow. The evidence supports no claim of a new feature, preview, general availability, retirement, or changed runtime behavior. The External ID Cloudflare-integration update has no summary, so it cannot support a more specific claim.

  • Entra ID · General
    Manage DNS guidance limits redirection to individual host names

    The updated Manage DNS guidance says not to redirect DNS zones related to windowsazure.com or core.windows.net. If redirection is required, it says to limit it to individual host names—for example, server1.file.core.windows.net rather than file.core.windows.net. This is explicit networking guidance, not evidence of a new enforcement mechanism.

  • Entra ID · Conditional Access
    Conditional Access sign-in-log terminology is clarified

    The updated Sign In Log Activity Details page defines Success as the Conditional Access policy being applied successfully to the sign-in attempt. This is a documentation clarification for interpreting existing sign-in records; the evidence does not indicate that Conditional Access evaluation changed.

  • Entra ID · Monitoring
    Graph activity-log troubleshooting calls out email-validation sign-up failures

    The updated How to Analyze Activity Logs with Microsoft Graph guide calls out how to find sign-up attempts that failed during email validation. This provides troubleshooting coverage for a specific failure path, but the record does not indicate changed sign-up behavior or a new rollout.

  • Global Secure Access · Developer
    Global Secure Access documents the Application Discovery-to-private-app workflow

    The updated Application Discovery for Global Secure Access page says to use Application discovery to detect applications accessed by users and create separate private applications. It documents a capability workflow; the supplied evidence does not establish whether this is new, in preview, or generally available.
