Day in brief

Native Authentication V2 guidance now separates browser domain requirements from mobile clients

The 18 November updates were dominated by documentation revisions, but several have practical administrator value: Embedded Native Authentication V2 guidance defines the browser-versus-native domain split and lists MSAL.js 5.29.1; SSPR writeback guidance covers PHS staged rollout with Cloud Sync; PIM and Windows Server with Intune preview scope is clearer; and Global Secure Access now states concrete cloud-firewall limits. Remaining edits mainly refine terminology, navigation, links, or examples.

  • Entra ID · Authentication
    Embedded Native Authentication V2 migration clarifies browser domains and MSAL.js minimum

    The migration page now states that browser-based apps require a tenant-verified custom domain, while native Android and iOS clients can use their configured service authority without a custom domain or CORS proxy. It sets the listed MSAL.js minimum at 5.29.1.

  • Entra ID · Authentication
    SSPR writeback guidance documents PHS staged rollout with Cloud Sync

    The on-premises password writeback page now states that SSPR password writeback is supported for users in PHS staged rollout when Microsoft Entra Cloud Sync is used.

  • ID Governance · Fundamentals
    PIM guidance documents preview agent access and Bastion session controls

    The identity governance overview now covers PIM preview support for just-in-time Azure resource access by agents and agent identities, along with Azure Bastion session analytics, recordings, and session disconnection.

  • Entra ID · Conditional Access
    Windows Server with Intune preview guidance flags possible automatic enrollment

    The Arc sign-in guide now links to the current preview resource and says qualifying devices might be automatically enrolled when the Entra extension is deployed. Administrators evaluating the preview are directed to review its scope and enrollment guidance.

  • Global Secure Access · General
    Global Secure Access cloud firewall documents tenant and per-rule limits

    The current limitations page now states that cloud firewall supports up to 1,000 rules per tenant and a combined total of 500 sources and destinations per rule.
