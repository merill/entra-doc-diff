Day in brief

Agent Conditional Access guidance now separates agent identities, user accounts, and OBO traffic

Agent Conditional Access is the clear center of the 7 October update: a new Entra ID guide covers agents operating through their own user accounts, while Agent ID guidance separates agent identities, agent user accounts, and delegated or on-behalf-of access. The guidance directs administrators to match policy targeting to the token subject and check the stated licensing, role, device, network, registration, and OAuth prerequisites. A separate authentication update refreshes FIDO2 attestation data.

  • Entra ID · Conditional Access
    New guide requires separate targeting for agent user accounts

    The new Entra ID Conditional Access guide covers agent risk, compliant devices, and compliant networks for agents that use their own user accounts. It states that policies targeting all users do not include agent user accounts, so administrators must target agent users separately and satisfy the listed licensing, role, device, and network prerequisites.

  • Agent ID · Conditional Access
    OBO guidance assigns Conditional Access targeting to the signed-in user

    Updated Agent ID guidance says the signed-in user is the token subject for on-behalf-of traffic, whether targeted directly or through groups, and directs administrators to user-targeted policies for those resources. Selecting an agent identity is documented for a different access pattern.

  • Agent ID · Conditional Access
    Autonomous-agent policy guidance adds prerequisites and report-only blocking

    The revised guidance centers policies on agents using their own identities, adds licensing, role, registration, and OAuth prerequisites, and recommends report-only block policies for unapproved agents.

  • Entra ID · General
    Policy guidance lists current licensing options and an upcoming Agent 365 requirement

    The Policy Autonomous Agents page lists Microsoft 365 E7, or Microsoft Agent 365 paired with Microsoft Entra P1 or Microsoft 365 E3, and says Agent 365 will soon be required.

  • Entra ID · Authentication
    FIDO2 attestation reference moves to MDS 285 and adds five models

    The attestation page now references MDS version 285 instead of 279 and adds five FIDO2 security-key models with their AAGUIDs and capability indicators. Administrators evaluating key attestation should use the updated identifiers.
