Month in brief

TLS inspection guidance separates Microsoft-managed and customer-owned certificate paths

September’s main change was a reworked Global Secure Access TLS inspection documentation set. A new guide covers a tenant-specific Microsoft-managed root CA for Microsoft Entra Internet Access, while companion pages separate that path from bringing your own certificate authority. The managed-certificate capability is described as being in preview, and the setup requires deploying the public root certificate to client devices before enablement. The period also added certificate-choice guidance to prompt injection protection documentation and corrected a Connect Health download link; a custom-header edit only standardized spacing.

  • Global Secure Access · Security
    A dedicated guide documents Microsoft-managed TLS inspection certificates

    The new Global Secure Access guide explains how to create a tenant-specific Microsoft-managed root CA, deploy its public certificate to client devices, and enable it for Microsoft Entra Internet Access TLS inspection. It identifies the capability as being in preview and says Microsoft protects the private key.

  • Global Secure Access · Troubleshooting
    TLS inspection navigation now branches by certificate choice

    The troubleshooting documentation now links separately to the Microsoft-managed certificate procedure and the customer-provided certificate procedure, helping administrators select the guide that matches their configuration.

  • Global Secure Access · Security
    The own-certificate procedure now spells out the PKI workflow

    The updated guide focuses on bringing your own certificate authority, including certificate signing request creation, PKI signing, and certificate upload, and links to the separate Microsoft-managed certificate guidance.

  • Global Secure Access · Security
    Prompt injection protection guidance adds both TLS certificate options

    Before configuring TLS inspection policies for enterprise generative AI apps, the documentation now explains that administrators can use either a Microsoft-managed certificate or an administrator-provided certificate.

  • Entra ID · General
    Connect Health roadmap switches both agent links to download ID 108777

    The Entra ID Connect Install Roadmap now directs both the AD FS and AD DS Connect Health agents to download ID 108777, replacing download ID 108565.

For Entra administrators

Choose the TLS inspection procedure that matches your certificate model. With the Microsoft-managed option, deploy the root CA’s public certificate to client devices before enabling inspection to avoid certificate errors; Intune or another MDM can be used. Administrators using their own PKI can follow the documented CSR, signing, and certificate-upload workflow. Entra Connect administrators using the roadmap should use download ID 108777 for both AD FS and AD DS Connect Health agents instead of 108565.
