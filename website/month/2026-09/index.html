Month in brief

Passkeys become Entra default as SMS retirement and Connect deadline loom

September’s highest-impact Entra developments were authentication and service-continuity changes: passkeys became the default on September 1, Microsoft-provided SMS and voice authentication moved toward 2027 retirement, and updated Connect guidance tied synchronization to application-based authentication by April 7, 2027. Microsoft Graph also narrowed User.ReadBasic.All, while a mid-October sign-in security change will block external script injection. A new Entra ID preview tutorial adds cloud-managed provisioning into AD DS for access to an on-premises Kerberos application.

  • Entra ID · Conditional Access
    Passkeys are default; Microsoft-provided SMS and voice retire in 2027

    Microsoft says passkeys became the default Microsoft Entra authentication on September 1, 2026. Microsoft-provided SMS and voice authentication are scheduled to retire on February 1, 2027; organizations that still need those methods must move to telecom providers from the Microsoft Security Store.

  • Entra ID · Authentication
    Soprano and Telesign named initial SMS and voice providers

    The updated retirement guidance names Soprano and Telesign as initial private-preview providers and says provider selection and configuration through Microsoft Security Store begins October 30, 2026.

  • Entra ID · General
    Connect guidance sets an April 7, 2027 application-authentication deadline

    The updated prerequisites page changes the stated minimum Entra Connect Sync version from 2.5.79.0 to 2.6.84.0 or later and requires application-based authentication by April 7, 2027. It says synchronization services will stop after the deadline if the requirements are unmet.

  • Entra ID · Microsoft identity platform
    User.ReadBasic.All loses app-role and license-detail access

    From mid-September 2026, User.ReadBasic.All no longer allows applications to read user app role assignments or license details. Applications that need those properties must use User.Read.All or LicenseAssignment.Read.All instead.

  • External ID · Authentication
    Entra sign-in will block external script injection in mid-October

    Microsoft Entra will enforce a Content Security Policy on login.microsoftonline.com starting mid-October 2026, allowing only trusted Microsoft scripts to run. Organizations using script-injecting tools on that sign-in surface should review compatibility; no action is needed when they do not use such tools.

For Entra administrators

Prioritize an authentication-method inventory, including users who may need a customer-managed telecom provider or phishing-resistant replacement, and review the October 30 provider-selection milestone. For Connect, verify the applicable minimum version—September entries cite both 2.5.79.0 and 2.6.84.0—then configure application-based authentication before April 7, 2027. Audit applications using User.ReadBasic.All and update permissions where the removed data is needed. Assess any tools injecting scripts into login.microsoftonline.com before the mid-October change.
