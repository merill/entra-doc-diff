Month in brief

May 2026: actionable-message token retirement leads the period’s consequential Entra changes

May was primarily a documentation-maintenance period, but several Message Center notices describe concrete behavior changes. External access tokens for actionable messages are being replaced by Microsoft Entra authentication; federatedTokenValidationPolicy defaults tighten in mid-August; Conditional Access will apply during Windows Hello for Business and macOS Platform SSO registration in July; and App Instance Lock will be enabled by default for new applications in June. Dataverse Agent users are a separate Microsoft Entra Agent ID public preview with phased rollout. Most Learn edits clarify existing authentication, Conditional Access, External ID, Agent ID, and Global Secure Access guidance rather than announcing tenant-wide changes. The five removed items have no supplied detail establishing another product retirement. An early-access Power Apps and Dynamics 365 in-app-skills control was scheduled to move to a new underlying service on May 21 in preparation for GA, not as a GA announcement.

  • Entra ID · Authentication
    External access tokens for actionable messages are being retired

    Retirement and breaking integration change: Microsoft is replacing external access tokens with Microsoft Entra authentication. Messages that continue using legacy tokens will fail. The notice lists May 15, 2026 as the retirement date and June 8, 2026 as completion of the phase-out.

  • Entra ID · Conditional Access
    Conditional Access will apply during Windows and macOS identity registration

    Scheduled behavior change: starting July 6, 2026, with rollout completion scheduled for July 13, Conditional Access policies will apply to Windows Hello for Business and macOS Platform SSO registration. The notice specifically calls out requirements such as MFA and trusted locations during enrollment.

  • Entra ID · Authentication
    Federated sign-in validation will use stricter defaults

    Scheduled security hardening: beginning in mid-August 2026, Microsoft Entra will enforce stricter federatedTokenValidationPolicy defaults and block federated sign-ins when internalDomainFederation does not match the user’s UPN domain. The stated scope is tenants with federated domains configured before December 2025.

  • Workload ID · Authentication
    App Instance Lock becomes the default for new applications

    Scheduled default change for June 2026: new applications will have App Instance Lock enabled to protect sensitive properties from unauthorized changes outside the home tenant. Existing applications are explicitly unaffected, and administrators can disable the lock if needed.

  • Agent ID · Microsoft identity platform
    Dataverse Agent users enter public preview

    New capability, public preview—not GA: Dataverse Agent users are powered by Microsoft Entra Agent ID. The rollout was scheduled to start May 4, 2026, and was expected to reach North America by May 22; the notice describes a phased preview rollout rather than general availability.

For Entra administrators

Prioritize integrations using legacy actionable-message tokens: the notice lists May 15, 2026 as the retirement date and June 8 as completion of the phase-out, and says messages using legacy tokens will fail. Affected integrations need to move to Microsoft Entra authentication. Before the later rollouts, federation administrators should check the stated scope—federated domains configured before December 2025—for internalDomainFederation and UPN mismatches; enrollment teams should test Conditional Access requirements such as MFA and trusted locations during Windows Hello for Business and macOS Platform SSO registration; and application-creation automation should be reviewed for App Instance Lock.
