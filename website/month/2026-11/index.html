Month in brief

Microsoft sets February 2027 retirement for Entra SMS and voice SSPR

Microsoft will retire its own SMS and voice authentication for self-service password reset beginning in February 2027, with each user group receiving a 50-day transition. Entra Private Access now has preview guidance for sign-in-every-time reauthentication, while new documentation covers customer-owned telephony setup, a Salesforce provisioning deadline, and an RHEL upgrade failure mode affecting Entra SSH sign-in. Most remaining changes were link, command, and procedure maintenance.

  • Entra ID · Conditional Access
    Microsoft-provided SMS and voice SSPR authentication enters retirement

    Microsoft Entra ID will begin retiring Microsoft-provided SMS and voice authentication for SSPR in February 2027. Each user group has a 50-day transition, after which those methods will no longer be available for SSPR. Administrators should prepare alternative recovery methods.

  • Private Access · Conditional Access
    Private Access sign-in-every-time preview sets client and reauthentication requirements

    The preview requires Conditional Access and the Global Secure Access Windows client version 2.34.222 or later. It uses a five-minute reauthentication window; administrators should account for supported clients and platform-specific exclusions when deploying it.

  • Entra ID · Authentication
    Customer-owned telephony receives an end-to-end setup guide

    The new Microsoft Entra admin center guide covers purchasing and activating a telecom provider, deploying the Azure integration, configuring authentication method profiles, validating evaluation mode, and gradually rolling out SMS and voice delivery. It gives administrators a single procedure for reviewing the required Azure resources, tools, permissions, and tests.

  • Entra ID · Provisioning
    Salesforce provisioning guidance adds a December 1 permission deadline

    The Salesforce provisioning guide now calls for SOAP API `login()` and the **Use Any API Auth** permission on the Admin Username account. It documents Salesforce’s December 1, 2026 requirement and related credential-validation failures, so the permission should be in place before that date.

  • Entra ID · Authentication
    RHEL in-place upgrades can break Entra SSH sign-in

    The updated Linux guidance says an in-place upgrade from RHEL 8.x to 9.x can remove the `aadsshlogin` package and cause `Permission denied (publickey)`. If that occurs, administrators should uninstall and reinstall the AADSSHLoginForLinux extension.

For Entra administrators

Inventory users relying on Microsoft-provided SMS or voice for SSPR and plan alternative recovery methods around each group’s 50-day transition. For Private Access, verify the required Windows client and Conditional Access design. Teams using customer-owned telephony can follow the new end-to-end setup guide. Salesforce administrators should grant the documented permission before December 1, 2026, and Linux administrators should reinstall the AADSSHLoginForLinux extension if Entra SSH sign-in fails after an affected RHEL upgrade.
